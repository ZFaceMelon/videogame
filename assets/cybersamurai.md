Cyber Samurai - Asset Integration Reference

Overview

This document defines the mathematical and hierarchical structure of the CyberSamurai.glb asset for parsing in the custom C++ graphics engine and controlling via the OCaml state machine.

1. Scene Graph / Hierarchy

The glTF file contains a strict hierarchy. The parser must identify the following specific nodes by string name to establish pointers for the state machine.

Armature.004 (Root Skeleton / Armature Node)

samurai (Skinned Mesh - The main character body)

sheath (Mesh - The scabbard, driven by spine bone)

socketsheath (Transform Node - The resting position for the Katana. Local transform is baked. Target this for "Stowed" state).

sockethand (Transform Node - Parented to the right-hand bone. Local transform is baked. Target this for "Drawn/Combat" state).

2. Mathematical Baseline

Coordinate System: Y-Up (Standard glTF export).

Scale: The assets have arbitrary local scales (they were not normalized to 1.0 in Blender), but they are sized properly relative to each other visually. The C++ parser must read and apply the scale vectors from the glTF node data. If implementing dynamic weapon swapping, ensure the math accounts for parent scale inheritance to prevent the Katana from shrinking or growing when attached to a scaled parent like the Armature.

Origin Alignment: The Katana's origin point (0,0,0 local) is set exactly at the hilt.

3. Weapon Swap Logic (OCaml State Machine)

The animation file DOES NOT contain the sword geometry jumping between the back and the hand. The OCaml state machine must handle this logic programmatically:

Stowed State: Katana parent pointer is set to socketsheath. Local transform matrix is zeroed out.

Equip Action: Trigger the onearmequip animation.

State Swap: At the specific frame/timestamp where the hand passes the scabbard, reassign the Katana's parent pointer to sockethand and zero out its local transform matrix.

4. Animation Dictionary

The file contains the following shielded Actions. Use these exact string keys for the Animation Controller enums/hash map:

Locomotion & Idle:

breathingidle

fastrun

armedrunforward

armedrunback

combatwalkleft

combatwalkright

Combat & Actions:

onearmequip (The draw animation)

overheadslash (Attack)

twistflip (Dodge / Acrobatic)

(Note: There may be an empty 0 Action track or Action generated by Blender defaults. This can be ignored by the parser).

5. Blending Requirements

The C++ animation system must implement LERP (for translation vectors) and SLERP (for quaternion rotations) to crossfade between these animations. Snapping directly from fastrun to breathingidle without a ~0.2s blend weight variable will result in a visual glitch.
